# 验证与验收口径

## 当前提交版

运行方法见 [README](../README.md#quickstart)，自动检查和复现范围见 [交付与复现说明](delivery.md)。完整回归必须零失败、零错误、零跳过，且启用真实 Docker；普通无 Docker 测试不代表全流程通过。

## 单次算法任务

1. 需求在支持范围内，配置经过用户确认；来源、任务、类别和参数一致。
2. 方案和代码通过结构、依赖及静态检查。
3. 在批准镜像中真实训练和预测，接口与异常输入检查通过。
4. 主机独立计算指标，达到运行前冻结的门槛；同种子结果稳定。
5. 只按验证集比较及修复；代码版本和错误保留，预算不足明确停止。
6. 若选择最终测试，冻结获选版本后仅预约一次，不使用测试结果继续调参。
7. 知识回写完成，报告和模型来源可追溯；试用与当前任务绑定。

validated 表示验证集通过，accepted 表示本次最终测试也通过；failed/stopped 不得当作成功。各任务使用不同标签及样本范围，成绩不可直接横向比较。

[真实 API 案例](../examples/banking-classification/comparison/report.md) 包含真实错误修复、候选比较、最终测试与回写。[经验对照摘要](../examples/experience-reuse/historical-summary.json) 属于历史小规模实验：机制通过，未观察到指标或修复次数改善。

[示例目录](../examples/README.md) 区分完整可查看案例、节选证据和历史归档。不能把不同版本测试数相加，或把历史测试说成本次重新执行。不能用 Mock 的固定响应证明 LLM 语义理解；也不能用一次 API 成功保证后续任意响应正确。
