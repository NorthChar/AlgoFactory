# 系统架构与实现边界

AlgoFactory 是面向英文银行咨询分类的算法开发原型。用户确认的需求决定任务配置；LLM 负责理解和生成，生成的 scikit-learn 分类器负责训练与预测。BANKING77 用于训练和评价分类器，不用于微调 LLM。

## 从需求到成果

```text
用户描述 → 理解 / 补充问答 → 逐项复核 → 用户确认
    → 冻结目标、类别、参数和评估协议
    → 检索能力知识 → 规划 → 生成代码
    → 静态检查 → Docker 训练与预测 → 主机独立评分
    → 有限修复 / 候选比较 → 可选的唯一获选版本最终测试
    → 知识回写 → 代码、报告、模型及隔离试用
```

自然语言入口每轮最多两次 API 请求、最多三轮，无自动重试。离线入口只接受明确支持的表达。无法理解、超出范围或需求与页面选择冲突时阻止生成；用户修改需求或设置后必须重新确认。确认摘要用于绑定配置，不是身份认证。

## 模块与职责

| 模块（位于 src/algofactory） | 输入、输出与职责 |
| --- | --- |
| web / cli | 页面与命令行；提交任务、展示进度、下载成果、试用模型 |
| requirement_understanding / requirements | 用户原文、补充与支持范围 → 可执行配置或问题；保留逐项解释与复核 |
| experiments / tasks / banking | 分类目标、参数与固定数据 → 独立数据清单、标签映射、配置散列 |
| llm | Mock 或 API 结构化调用、认证、调用计数与预算；失败不静默切换 |
| schemas | Pydantic 契约：任务、方案、知识、代码版本、验证结果与经验 |
| knowledge | 文档抽取、来源校验、结构化检索；SQLite 为事实源，NetworkX/GraphML 为图视图 |
| planning / generation | 检索依据和配置 → 方案、build_pipeline(config) 代码及修复版本 |
| orchestrator / search | 显式状态机；候选尝试、有限修复、验证排序与最终测试预约 |
| execution | 受限 AST 检查、Docker 运行、资源限制、执行结果与模型保存 |
| validation / final_test | 主机独立评分；功能、指标、稳定性和接口四维检查；最终测试隔离 |
| experience / experience_reuse | 保存成功与失败；核验修复来源、协议和版本后才能复用经验 |
| reporting / web/models | 结构化及中文报告；校验来源后在容器内加载模型进行预测 |

知识、构建、审查是三个逻辑角色，由显式编排驱动；审查主要是确定性程序，不是三个独立自治 Agent。SQLite 减少部署依赖；Pydantic 把接口要求变成可执行校验；Docker 约束生成代码的执行；Streamlit 提供本地 Python 页面。

## 知识图谱

| 实体 | 主要内容 |
| --- | --- |
| Task / Capability | 任务、能力描述、输入输出、适用条件、指标 |
| Algorithm / Dependency | 算法、适用场景和依赖 |
| Dataset / Implementation | 数据协议、代码散列、版本和父实现 |
| ValidationRun / FailureCase | 实测指标、状态、失败类别和报告引用 |
| Experience | 条件、修复动作、结果、来源及验证状态 |

主要关系为 REQUIRES、IMPLEMENTS、APPLICABLE_TO、USES、DEPENDS_ON、DERIVED_FROM、EVALUATES、USES_DATASET、REPORTS。确切字段和可连接实体类型以 [Schema](../src/algofactory/schemas/knowledge.py) 为准。

来源保留内容散列、原文字符区间和精确引用。文档抽取仅允许任务、能力、算法、依赖，不接受模型自行编造的运行历史。运行实体由可信执行结果写入。事务确保实体、关系和工作流记录一致；重复写入幂等。见 [JSON](../examples/knowledge/knowledge.json) 和 [GraphML](../examples/knowledge/knowledge.graphml) 示例。

## 数据、执行和评估

当前支持完整 77 类、选定 2–76 类、单个意图与其他已知意图的二分类。派生任务保持原划分及 row_id，仅筛选或重映射标签；不能把其他已知意图当作任意未知意图。详见 [目标说明](intent-goals.md)。

TF-IDF + Logistic Regression / MultinomialNB 是批准的文本候选。词表只在训练集拟合，生成模块返回 sklearn 兼容流水线。训练数据、评估特征和配置按最小范围挂载；评估标签留在主机，生成代码不能自行评分。协议、候选参数、数据指纹与标签顺序冻结后再执行。

验证阶段检查真实 fit/predict、输出长度与概率、同种子重复性和异常输入。只根据验证集修复或排名；每候选最多两次修复，另受总尝试和 API 请求上限约束。最终测试可选，每个独立工作流仅预约一次获选版本；失败后不根据测试成绩改选。通过、失败和停止均留下报告，下载到代码不代表验收通过。

召回优先只用于单个意图任务：类别权重或先验改变训练，Recall 改变排序，独立门槛仍生效；同时展示误报，不能承诺效果提升。

## 经验与模型边界

经验复用核验失败和修复版本的直接来源链、代码及产物散列、同一评估协议。仅有实测支持的规则可成为 verified；新经验供后续运行使用。已有开关对照验证机制可用，未观察到修复次数或指标收益。派生分类任务暂不消费旧 77 类任务的经验。

模型绑定代码、训练数据、类别、参数和依赖环境；只在容器内序列化或加载，不接受用户上传任意模型。试用绑定本任务选定且通过验证的版本，失败任务不借用别的模型。历史未保存模型时需显式重新训练，并标明来源。

## 隔离与扩展

容器非 root、禁网、根文件系统只读、输入只读挂载、临时目录可写，限制 CPU/内存/PID/时间并移除 capabilities。缺失或过期镜像拒绝执行。静态检查与容器限制不构成绝对安全保证；部分资源异常仅有模拟测试。

模板和指标通过可信显式注册表扩展，不由网页动态导入第三方 Python。合成客户流失二分类和回归检查公共流程兼容性，不是额外完整业务产品。未实现任意数据上传、新业务自动适配、自治多智能体、Beam/MCTS 或生产服务部署。
