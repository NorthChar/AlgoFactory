# ADR-002：在已验收原型之上增加可操作的工作台

- 日期：2026-10-30（Asia/Shanghai）。
- 状态：增量方向 accepted；Phase 7 尚未实现。当前首页及七步证据展示纳入 0.6.1。
- 来源：用户实际操作后指出“只能固定任务”“不清楚一万多条数据用来干什么”，并要求开始下一步、同步 Git 和说明文档、基于原规划重新安排计划。
- 关联：[总体计划](../implementation-plan.md)、[Phase 7](../phase7.md)、[需求矩阵](../requirements-matrix.md)。

## 决策

保留 Phase 1–6 的完成状态、原题资料及历史验收。将工作台的操作能力作为 Phase 7 产品增量，按数据浏览、分类体验、可配置实验依次推进；每一步通过自己的验收门槛后再开始下一步。0.6.1 记录已经完成的用途说明、七步证据浏览、预算配置修复；0.7.0 是 Phase 7 完成后的目标版本，不能提前声称发布。

原题要求在一个行业案例内展示完整流程，并未要求通用无代码机器学习平台。新增功能对应用户体验和可验证性提升，支撑 T06、A03、A05、X06、X07；不将新功能描述为之前遗漏的强制基础项，不将现有三逻辑角色扩写为独立自治多智能体。

## 当前限制与实现影响

现有工作台只支持预设 BANKING77 与合成回归协议；客户流失保留 CLI 兼容检查。API 可解析同协议下的需求，但不能用需求文字任意改变字段、标签、门槛或候选参数。生成代码及验证结果已保存，隔离 worker 目前不导出训练后的模型。分类体验需要新增可信模型产物、版本绑定及隔离推理路径。

BANKING77 原始 13,083 条；移除训练侧重复及跨测试重叠 11 条后，训练 7,993、验证 1,999、官方测试 3,080 条。训练用于拟合分类器，验证用于比较和修复，测试仅在冻结选定版本后用于最终评估；这些数据不用于微调 GPT-4o。算法知识文档与业务数据须在界面中明确区分。

## 不变的边界

新页面不重写原始数据、历史报告或旧配置，不在浏览时自动训练、调用 LLM 或执行最终测试。数据探索首先开放训练和验证样本，测试集仅展示规模和冻结状态，不默认开放逐条标签与错误分析。预测体验不能成为绕过最终测试访问记录的入口。

保存和加载模型只使用项目自身可追溯的产物，绑定代码、数据、参数、依赖、类别映射和模型散列；不接受外部序列化模型，不在宿主直接执行生成代码或反序列化不受信任模型。模型准备、预测、异常与超时仍经过隔离和资源限制。

自定义实验首轮只允许已有两种文本分类候选及经过审查的参数范围。配置进入真实编排、提示、静态检查、worker、报告和回写，不能只改变页面。实验前冻结配置；不依据官方测试结果调整候选、参数或阈值。

本轮不加入任意 CSV 上传、任意任务自动适配、在线客服自动回复、公网部署、中文/未知意图识别或新的付费 API 实验。额外加分项在 Phase 7 后按收益和工作量择优，不先行承诺全部实现。
