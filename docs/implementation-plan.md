# AlgoFactory 总体实施计划

本项目面向 Mac M5 Pro 48GB 的本地演示，以客户流失预测证明能力抽取、代码复刻、独立验证与知识沉淀的完整闭环。先冻结问题、契约和验收，再分阶段实施。当前交付仅为 Phase 0 文档及工程骨架，核心流程尚未实现。

## 问题定义与目标

输入为自然语言能力描述、CSV 数据、字段说明与任务约束；知识包含能力、适用条件、算法、依赖、历史验证和失败经验。输出为可加载 Python 实现、机器可读及中文验证报告、候选比较与版本轨迹，以及持久化知识更新。没有合格候选时明确失败，不能以代码生成完成代替算法验证通过。

主任务为表格二分类，预处理包含缺失值、类别编码与必要缩放。候选为 Logistic Regression、Random Forest、HistGradientBoosting，首个闭环先实现单候选，之后至少两候选比较。轻量合成回归任务实际运行以验证多任务配置。范围外为生产部署、本地大模型训练、任意仓库抽取、Beam/MCTS、跨模态迁移、自动部署和大规模性能优化。

基础要求全部列为必须；进阶选择 CLI、Streamlit、多轮修复、候选比较、图谱展示、报告、回写、多任务配置及模板和指标插件。加分选择三角色协作、失败经验复用、能力版本、安全隔离、解释溯源。跨任务回归仅用于验证配置机制，不声称完成跨场景迁移加分项。

## 阶段与退出条件

| 阶段 | 工作与交付 | 退出证据 |
| --- | --- | --- |
| Phase 0 问题与范围 | 原题存档、问题定义、需求矩阵、架构、验收、Demo 协议 | 每条基础要求有模块、产物及验收映射；来源校验通过 |
| Phase 1 架构与知识 | Pydantic 契约、SQLite 模式、抽取校验、检索、NetworkX 导出、API/Mock Provider | 文档抽取为实体关系；查询有来源；Provider 契约测试 |
| Phase 2 最小闭环 | CLI 需求解析→检索→规划→生成→隔离执行→四维验证→回写 | Demo A 真实产物与报告；Mock/API 使用同一编排器 |
| Phase 3 修复与比较 | 错误分类、有界修复、同协议候选排名、代码版本 | Demo B 失败→修复→重测；至少两个候选；停止条件测试 |
| Phase 4 经验复用 | 经验抽取、证据关联、条件检索、解释与对照 | Demo C 检索并使用历史经验；固定输入的开关对照 |
| Phase 5 界面与质量 | Streamlit、图谱、报告、插件与任务配置、异常恢复 | CLI/Web 主路径；回归任务；插件注册；安全拒绝及异常测试 |
| Phase 6 集成交付 | 冷启动、锁依赖、真实报告、README 完整内容、GitHub 提交准备 | G1–G5 全部有证据，干净环境复现 |

安全边界、数据划分和独立验证从 Phase 1–2 落地，不能推迟到 Phase 5 才执行生成代码。各阶段通过退出检查后形成清晰 Git 提交。下一阶段开始前更新矩阵状态，范围变化需记录理由及受影响 Gate。

## 资源与可复现性

Python 3.11 作为首个验证版本，采用标准 Python 编排器，避免额外 Agent 框架成本。SQLite 降低运维成本，NetworkX 支持关系遍历与导出，scikit-learn 支持 CPU 表格模型，Streamlit 用于演示。无需购买服务器或训练本地大模型。LLM 通过显式 Provider 在 Mock/API 间切换，Mock 使用固定响应和可控故障，API 使用环境变量密钥，禁止静默降级。

初始预算为两候选、每候选最多两次修复、生成代码每次执行 120 秒、容器 2 CPU/4 GiB、禁网。预算为待基线实测的起点，不是硬件性能承诺。API 设置调用次数、超时及费用上限；日志脱敏。Docker 不可用时阻止真实生成代码执行，可展示 Mock 轨迹但不能签署执行验收。

使用固定随机种子 42、确定性合成客户数据及可提交业务文档；记录生成器、数据散列、划分索引、模型配置与运行环境。训练/验证/测试初始比例 60/20/20，按二分类分层。预处理只在训练集拟合，候选及修复只看验证集；独立测试集在选定版本后一次评估。指标阈值先经训练/验证基线校准并冻结，禁止依据测试结果修改。

## 实施依赖与风险处理

先完成契约与知识来源，再实现单闭环，再加修复比较和经验复用。API 不可用应记录 blocked 状态及重试条件，不把 Mock 当真实 API 证据。回写使用事务、稳定 ID 与幂等键；取消或超时保留可诊断状态。经验仅在真实重测后标为 verified，推测建议单独存为 proposed。

正式依赖锁文件在 Phase 1 基于实际 Python/arm64 环境生成并验证；当前骨架不声称完整环境已锁定。GitHub 远端和发布在 Phase 6 配置，此次仅初始化本地仓库。

## 评分证据与后续动作

技术能力 40% 由真实闭环、图谱检索、修复与统一验证证明；代码质量 30% 由契约、错误处理、日志、测试及复现证明；创新性 15% 由三角色决策与经验复用对照证明；完整性 15% 由矩阵、文档、UI 和交付样例证明。先实施 Phase 1，禁止把当前骨架状态写成端到端完成。
