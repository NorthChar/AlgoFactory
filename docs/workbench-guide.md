# AlgoFactory 工作台使用指南

工作台当前完整落地的业务是 **银行客服英文咨询分类算法的代码生成与验证**，通过全部类别、指定类别或单个意图三个目标展示“理解需求 → 检索 → 规划 → 生成 → 验证与修复 → 回写”的闭环。不是任意业务代码生成平台；客户流失和合成回归用于公共框架兼容检查。本文对应 0.8.0 的需求确认与任务目标功能；复用生成、沙箱和修复流程，按确认目标筛选数据、重映射标签、冻结独立评估协议。

## 先理解两种输入

- **开发需求**：“请开发一个英文银行咨询分类算法，输出问题类别及概率，并验证分类效果。”系统交付分类代码、报告和通过版本的模型。
- **成果试用**：例如 `I lost my bank card.`，交给本次训练好的分类器预测。这是用途示意，不保证模型判断正确；试用不调用 GPT、不计入标准评估。

无需先研究数据集。BANKING77 是已准备好的训练与验收材料：数据接口约定代码处理什么字段，带标签的咨询让生成代码能实际训练和检查效果。没有用它微调 GPT，也不是把全部咨询发给 GPT 写代码。

## 自然语言需求与补充问答

先选择“完整意图分类”“指定类别分类”或“单个意图识别”，并选择相关类别。默认入口允许用自己的话描述业务目标，不要求记住固定句式或算法参数。例如：

> 我想把英文银行咨询自动分到已有的问题类别，输出类别和概率。我不懂算法，请帮我比较合适的方案。

大模型先逐项解释用户需求，给出方案或追问；程序检查是否覆盖每一段原文、是否属于支持的配置。可执行的提案再由单独一次模型调用复核是否遗漏、误解或擅自替换要求。这是同一接口的第二次复核调用，不是独立模型或人工评审；仍需用户核对，不能保证语义理解永远正确。

- 没有指定算法、希望系统选择：可以建议比较现有两个候选，参数显示为系统建议。
- “希望运行快一点”：应追问可接受的具体要求，不能声称缩小词表就保证速度。
- 中文、新业务、自有数据、新类别或保证准确率：当前不能据此生成；必须说明不支持或需要澄清。模型理解自然语言不会扩展实际算法能力。
- 用户补充明确撤回旧限制后，可以重新检查；原文、补充、逐项处理、复核和最终确认均保留。

### 调用与费用

“理解我的需求”每轮最多两次 API 请求（理解、必要时复核），无自动重试。每条原始需求最多两次补充，共三轮、最多六次请求；只在点击标明费用的按钮后调用。每轮先保存记录，刷新或同轮重复请求返回已有结果；失败或中断不会自动重放。修改原始需求会开始新的检查，费用另计。

后面的代码生成有单独的预算。即使选择 Mock 生成代码，自然语言理解步骤仍可能已产生 API 费用。想全程免费体验，应选择“离线示例与固定表达”；此入口沿用本地规则，不调用 LLM，不假装理解任意表述。

## 第一次操作

1. 打开 `http://127.0.0.1:8501/`，点击“开始开发银行分类算法”。说明你要解决的问题、输入输出及限制，不是输入一条待分类的咨询。
2. 选择自然语言理解或离线检查。自然语言方式需先配置接口及密钥；点击付费理解按钮才调用。无需 API Key 的体验请选择离线方式。
3. 阅读系统理解及逐项解释。如果有追问，在“补充说明或回答问题”填写后再次提交；未明确或不支持的方案不能生成代码。
4. 核对目标、所选类别、建议配置和训练/验证数量，区分“模型从需求提取，请核对”与“系统建议，请确认”。选择与文字不一致时需澄清，不能自动退回全量任务。
5. 选择 Mock 或 API 生成代码，核对评估方式、修复次数、请求预算和经验复用。勾选确认后开始。修改需求、补充内容或运行设置后需要重新确认。
6. 在本次任务查看原始需求、用户补充、确认方案、代码及报告；“开发过程”查看修复链，“试用本次算法”使用通过版本。未通过任务不会借用其他任务模型。

`runtime/requirement-drafts/` 保存每轮原文、方案、复核结果及调用用量；任务中的 `confirmed-requirement.json` 保存原始描述、补充、确认配置和规范化执行要求。模型生成流程使用经过配置检查的规范化描述，`requirement-origin.json` 记录它与用户原文的对应关系。确认摘要防止陈旧配置误提交，不是身份认证或数字签名。

### 离线表达示例

```text
开发英文银行咨询分类算法；输出77类意图及概率。
只使用逻辑回归；仅使用单词特征；词表上限10000；逻辑回归C=1。
```

离线模式逐句匹配页面列出的表达；未知、冲突、越界语句会阻止提交。它可验证配置贯穿生成与训练的流程，但不能替代自然语言理解验收。

## 参数选择与实验边界

| 可选项 | 支持范围 | 实际影响 |
| --- | --- | --- |
| 算法 | 逻辑回归、朴素贝叶斯、两者 | 单候选实验或同配置的双候选比较 |
| 文本特征 | 单词；单词和相邻双词 | TF-IDF 的 ngram_range |
| 词表上限 | 10,000；30,000 | TF-IDF max_features |
| 逻辑回归 C | 1.0；4.0 | 正则化强度，越小越强 |
| NB 平滑系数 | 0.1；0.5 | MultinomialNB alpha |
| 修复次数 | 每候选 0–2 次 | 接口错误修复与预定 NB 优化预算 |

NB 若因验证指标不足进入优化，alpha 最多按初始值、初始值的 1/2、初始值的 1/10 尝试。这个规则在提交前固定。选择单一算法不代表该算法“比较获胜”。每次实验显示配置编号，不把不同实验直接合并排名。

自然语言方案先经复核和用户确认，再转换为严格匹配实验配置的执行要求。离线新需求必须完整匹配本地规则。CLI 传非标准 `--request` 时必须同时传匹配的 `--experiment`，不匹配或缺少绑定会在配置 API 前拒绝；固定历史示例保持兼容。工作台额外要求用户确认全部当前运行设置。

## 使用 CLI 复现

在项目根目录、已安装依赖、导入数据并批准镜像后：

```bash
.venv/bin/python -m algofactory.cli demo --task banking77 --mode mock \
  --experiment configs/experiment-baseline.json \
  --validation-only --max-repairs 1 --llm-call-budget 12 \
  --output-dir runtime/my-experiment --db runtime/my-experiment.sqlite
```

输出目录必须是新的。另一套已冻结的示例配置为 `configs/experiment-unigram.json`。这两套配置用于验证配置流确实生效，不表示后者优于默认值。

分类目标与模型试用复验：

```bash
.venv/bin/python scripts/verify_intent_goals.py --output-dir runtime/goals-check
ALGOFACTORY_DOCKER_TESTS=1 .venv/bin/python -m pytest -q
```

脚本包含真实后台工作台任务及容器执行，页面另由完整回归中的 AppTest 检查，耗时取决于本机环境；不调用付费 API。它只验证训练和验证集流程，不新增最终测试。

## 常见情况

- **升级后页面仍报旧错误**：停止并重新启动工作台服务，仅刷新浏览器不足以重载所有 Python 模块；已有任务与报告保留。
- **镜像未准备或过期**：按 README 重建批准镜像。worker 变化后旧镜像不能继续用。
- **模型缺失或环境不匹配**：在所选任务的“试用本次算法”中显式准备或重新准备该版本。旧产物保留，系统不会静默换版本。
- **输入被拒绝**：输入非空、1–1000 字符的英文咨询，不要复制冻结测试集文本。原型只支持已知意图，没有未知类别识别能力。
- **请求预算耗尽**：查看已保留证据，再手动决定是否提交新任务。系统不会自动扩额。
- **验证未通过**：不把此模型当作合格试用版本；查看具体失败维度和修复记录。

真实 API 模式仍会产生费用。此次 Phase 7 新增功能用 Mock 验证真实执行，未新增付费接口实验。工作台是本机服务，GitHub 私有仓库不等于公网网页部署。

## 验证本增量

`pytest tests/test_requirements.py` 检查逐句覆盖、冲突拒绝、陈旧确认、配置传递和页面提交门槛。准备好 Docker、镜像和 BANKING77 后，可以运行：

```bash
.venv/bin/python scripts/verify_requirements.py --output-dir runtime/requirements-check
```

使用全新输出目录。两条不同需求分别执行真实训练；逻辑回归案例通过 Mock 显式注入接口故障检查修复，不代表真实 LLM 自发错误。脚本只用 Mock，不产生 API 费用，不执行最终测试。这段脚本不调用真实 API，也不代表独立新手可用性验收。自然语言理解另有测试 `tests/test_requirement_understanding.py`，覆盖补充问答、完整覆盖检查、复核拒绝、确认绑定、失败不重试及执行桥接。


## 可选择的开发目标

见 [任务目标与复验说明](intent-goals.md)。选择会实际影响数据、标签、任务契约、模型训练、评分和模型试用。全量训练集不复制到指定类别模型中；单个意图识别保留其他 76 类作为负类。语义理解仍有限制，需要用户确认；不能用未知意图检测、交易风控等未支持要求替换已实现目标。
