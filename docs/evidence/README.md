# 规划依据与数据初检证据

2026-10-28-dataset-audit.json 是 2026-10-28 下载候选公开数据后的原始结构检查结果，从本地 runtime/dataset-review-20261028/audit.json 原样归档。它支持 [ADR-001](../decisions/0001-banking77-main-case.md) 的案例选择，不是模型训练或端到端验收报告。

## 来源与重现口径

JSON 中 downloads 记录公开下载 URL、原始字节数、SHA-256 和成功状态。归档时逐个核对仍保留在本地 runtime 的下载文件散列；原始下载文件未加入 Git。BANKING77 当时按 master 下载，未记录提交 SHA，必须用文件散列辨认本次快照；后续正式导入需额外固定上游版本。

- BANKING77：使用 pandas 读取官方 train.csv 和 test.csv；检查缺失单元格、类别数和每类数量。文本归一化为 strip → casefold → 连续空白合并为空格。分别统计集合内部重复文本的冗余行数、训练/测试共有归一化文本的不同值数量，以及同文本对应多标签的组数。
- Iranian Churn：读取压缩包内 Customer Churn.csv，列名首尾去空白；Churn 作为目标，其余列作为特征。统计完全重复行冗余数、重复特征行冗余数、相同特征对应多标签的组数、标签分布及 Status/Churn 交叉表。同特征不同标签不直接判定为错误，因为原始客户身份未得到核实。
- Steel Plates Faults：按空白分隔读取压缩包中的 Faults.NNA；前 27 列作为特征，末 7 列为 one-hot 类别。统计缺失、完全重复及特征重复、标签行求和不为 1 的数量与各列标签计数。JSON 中 27–33 为原始列索引，名称可由同包 Faults27x7_var 对照。

本次未训练模型，未评估准确率或推理成本，未全面人工检查标签、语义近似重复、生产数据分布或潜在业务泄漏。数据来源和许可说明见 ADR-001 中的官方链接；公开数据的使用需保留相应署名与许可。
